## 1. 프로젝트 핵심

- **무엇**: 한국어 AI 회의 일정 조율 챗봇(NODI). 대화로 조건을 받아 추천 시간 후보를 보여주고, 사용자가 승인하면 확정한다. 반응형 웹 + 모바일 앱형 UI, 체험은 가상 캘린더·가상 조직(약 260명) 데이터.
- **스택**: React 19 · Vite 7 · TypeScript · Tailwind 4 · Express 5(`tsx`) · vitest + Testing Library · LLM은 Groq(서버 메모리 세션). 분석은 Amplitude Browser SDK 2(공개 프로토타입, 동의 후에만).
- **모드(`NODI_MODE`)**: `groq`(키 사용) / `demo`(키 없이 시나리오) / `public`(공개 테스트, 서버 키 프록시·사용량 보호). demo·public은 프로세스 임시 폴더 저장, 세션은 메모리(TTL 4시간).
- **핵심 규칙**
  - 검증 순서: `npx tsc -b` → `npx vitest run` → `npm run build`.
  - 사용자가 "커밋해줘/올려줘"라고 할 때만 커밋. 푸시는 사용자가 GitHub Desktop에서(터미널에 인증 없음).
  - 커밋에서 항상 제외: `NODI_CONVERSATIONAL_SCHEDULING_IMPROVEMENT.md`, `docs/design-snapshots/`. 커밋 끝 줄: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
  - 비밀 값(Groq 키, `OPS_TOKEN`, `SUPABASE_SERVICE_ROLE_KEY`)은 코드·로그·문서·채팅에 쓰지 않는다(`bash scripts/check-secrets.sh`).
  - 상태 용어 구분(일정 충돌 없음 ≠ 참석 가능 응답 ≠ 응답 대기 ≠ 확정). NODI 내부 확정과 외부 처리(캘린더 반영·초대 발송)를 따로 표시, 하지 않은 일은 "완료"로 쓰지 않는다.
  - `src/styles.css`는 나중 규칙이 이기는 누적 구조: 맨 아래에 기능별 주석 블록으로 추가.
  - 반응형 기준: 모바일 ≤767 · 태블릿 768~1199 · 데스크톱 ≥1200 (`src/useMedia.ts`와 CSS 값 동일).
  - 기존 문서는 덮어쓰지 않고 추가한다.
- **디자인 시스템**: Primary `#3654D4`, 텍스트 `#18243A/#47566D/#566580`, canvas `#F5F7FB`, border `#DDE4EF`, 폰트 Pretendard, 간격 4px 격자, 터치 44px 이상, CTA 48~52px. 굵기 700은 디자인 시스템 지정을 우선(unslop 기준 600 이하보다 우선하기로 결정).

- 리디자인 Phase 1 구현(`NODI-REDESIGN-MASTERPLAN.md`·`NODI-SCREEN-SPEC.md` 기준)은 별도 요청 전까지 시작하지 않았다.

- 짝수 off-grid 간격(6·10·14·18·22px)과 남은 음수 자간 23곳(큰 제목)은 그대로.
- 알림 서버 연동(실시간) 없음. 지금은 데모 가상 데이터와 화면에서 계산한 응답 현황만.
- Figma 알림 시트 디자인 없음. 기존 01~09 모바일 프레임은 수정 전 상태로 남겨 둠.
- 데모·공개 배포 반영: `demo`·`main` 푸시, `nodi-public` Manual Deploy.
- 공개 프로토타입 쪽 사용자 결정 대기 항목: 실제 Amplitude 프로젝트·키, 실제 Groq 키, Supabase 실제 연결, 보존 기간·문의처.

- iOS Safari·Android Chrome 실기기(키보드, Safe Area, 주소창, 홈 화면 추가), 태블릿(768~1199) 화면, 스크린 리더, 텍스트 200% 확대.

- Render 로그로 재시작 원인 확인, 실제 Groq 키로 자유 입력 품질.
