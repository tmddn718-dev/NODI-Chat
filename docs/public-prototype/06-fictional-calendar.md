# 가상 캘린더 fixture 설명과 초기화

1차 공개 테스트는 Google Calendar·Outlook 등 **실제 계정을 연결하지 않아요.** 모든 일정·사람은 가상이에요.

## 데이터 위치(재현 가능)
| 파일 | 내용 |
|---|---|
| `server/demo-data.ts` | 샘플 5명(고정 일정). 공개 테스트에서는 일정 날짜를 **오늘 기준 앞으로 올 두 주**로 같은 요일에 옮겨 항상 충돌이 보여요 |
| `server/org-data.ts` | 약 260명의 가상 조직(8개 본부·약 30개 팀). **시드 난수**라 같은 기준일이면 항상 같은 결과예요(`generateOrg(기준일)`). 직급·근무시간·휴가·팀 정기회의 포함 |
- 이름은 흔한 한국어 이름을 조합한 것이고 이메일은 `@nodi.demo`예요. 실제 인물·조직과 무관하며, 화면 위쪽 띠에 "테스트용 가상 일정이며 실제 캘린더에는 반영되지 않아요"를 항상 보여줘요.
- 일정은 "바쁨/한가함"만 쓰고 일정 제목은 서버 밖으로 나가지 않아요.

## 실제 캘린더·메일에 아무 일도 일어나지 않아요
- 캘린더 공급자는 가상 공급자뿐이고(외부 API 없음), 확정해도 **외부 캘린더 반영 전·초대 발송 전**으로 표시돼요(확정 완료 화면의 처리 상태).
- 메일 "발송"은 발송함 파일에 기록만 하고, 공개 테스트에서는 그 파일도 서버 임시 폴더에만 써요. 실제 메일 서비스 연동 코드가 없어요.
- 선택 참석자의 응답은 실제 사람이 하지 않아요: "가상 참석자 응답 받기" 버튼이 정해진 응답을 채워요.

## 시나리오별 재현 방법
| 상황 | 재현 |
|---|---|
| 여러 참석자가 모두 가능한 시간 | 필수 참석자 1~2명, 다음 주 범위 → 1순위 후보에 "필수 참석자 조건 충족" |
| 일부 일정 충돌 | 후보 카드의 "일정이 겹치는 사람 N명"/참고 후보, 후보 비교 표 |
| 적합한 시간이 없음 → 재탐색 | 날짜 범위를 오늘~내일(주말 포함)로 좁혀 후보 찾기 → "응답 마감 이후에 필수 참석자가 모두 가능한 시간이 없어요" → 기간을 넓히거나 "후보 새로 찾기" |
| 모바일 일정 밀도 | 375px 폭에서 후보 3개·참석자 시트·확정 화면 확인(QA 체크리스트) |
| 휴가·근무시간 밖 | 조직 구성원 중 휴가자는 해당 날짜가 "휴가·근무 시간 외"로 표시돼요 |

## 초기화
- 사용자: 설정 → **테스트 데이터 초기화**(내 가상 회의·입력을 지우고 새 작업 공간으로 시작). **다른 사람의 데이터와 분석 데이터에는 영향이 없어요**(작업 공간이 방문자마다 따로예요).
- 서버 전체: 서비스를 재시작하면 모든 가상 회의가 사라져요(메모리·임시 폴더 저장).
- 분석 이벤트와 피드백은 초기화와 별개로 Amplitude·결과 저장소에 남아요.

## 분석·문서에서의 표기
모든 분석 이벤트에 `test_mode: fictional_calendar`가 들어가요. 결과를 공유할 때 "가상 캘린더 기반 테스트"임을 명시하세요.
