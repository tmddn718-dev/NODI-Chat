# 파일럿(10–20명) 해석 가이드

## 이 숫자로 할 수 있는 것 / 없는 것
- **할 수 있는 것**: 어느 *단계*에서 사람들이 멈추는지 눈으로 찾기, 오류가 몰리는 곳 찾기, 소요 시간의 대략적 규모, 기기별로 *크게* 어긋나는 문제 발견.
- **할 수 없는 것**: 통계적 유의성 판단, "A안이 B안보다 10% 낫다" 같은 결론. 사용자 10–20명이면 한 명이 퍼센트를 5–10%p 움직여요.

## 읽는 법
1. 퍼널 단계별 **사람 수**(비율보다)를 먼저 보세요. "6명 중 2명이 멈춤" 식으로 읽어요.
2. 멈춘 지점이 보이면 `flow_abandoned.last_completed_step`과 `prototype_error`로 이유를 좁히고, **피드백 자유 의견**([11](11-feedback-check.md))과 맞춰 봐요.
3. 테스트 담당자 본인·개발자의 사용은 데이터에 섞여요. 가능하면 참여자에게 시작 시각을 받아두고 내부 사용 구간은 제외하세요.
4. `flow_abandoned`의 `page_hidden`은 근사치예요(탭 전환·새로고침도 포함될 수 있음). 이탈 수를 확정 수치로 쓰지 마세요.
5. 같은 사람이 여러 번 쓰면 사용자 수와 흐름 수가 달라져요. 퍼널은 Unique users 기준이에요.
6. 실험군은 인원이 너무 적어 *비교하지 마세요*. 실험은 최소 수십~수백 명이 모인 뒤 의미가 있어요.

## 권장 판단 기준
- 같은 문제를 **3명 이상**이 겪으면 개선 후보.
- 오류(`recoverable=false`)는 건수와 상관없이 즉시 확인.
- 개선 후 `flow_version`을 올려 다음 파일럿에서 이전/이후를 비교.
