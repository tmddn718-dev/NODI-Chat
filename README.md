# NODI Meeting Scheduler

자연어 대화로 회의 정보를 모으고, 데모 캘린더의 Free/Busy 데이터를 이용해 결정적 알고리즘으로 후보 시간을 추천하는 로컬 실행용 MVP입니다.

## 주요 기능

- Groq API Key 연결 테스트와 실제 모델 목록 조회
- `llama-3.3-70b-versatile` 기본 선택, 계정에서 사용할 수 없으면 첫 사용 가능 모델로 대체
- 한국어 및 영어 대화, 회의 필수 정보 추출
- 회의 종류, 목적, 시간, 참석자, 일정 확정 조건, 선호 시간대, 시작일, 종료일을 순서대로 안내하는 선택형 대화
- 각 단계에서 추천 목록 또는 직접 입력 방식 제공
- 최근 회의한 사람 우선 표시, 이름·이메일 검색, 다중 선택, 외부 이메일 참석자 추가
- 참석자별 가능, 불가, 미정, 미응답 수동 입력과 응답 진행률 표시
- 앱 설치 없이 열리는 참석자별 전용 응답 링크, 7일 만료, 응답 변경
- 캘린더 Free/Busy와 직접 응답을 병합하되 서로 다른 상태로 표시하는 결정적 후보 시간 계산
- 가상 직원 5명의 일정 충돌을 반영한 후보 시간 3개 계산
- 사람의 중요도가 아닌 `일정이 맞아야 회의를 진행할 수 있는 사람`을 조건으로 설정
- 일정 확정 조건 충족 여부를 추천 점수보다 먼저 판단하고, 조건 미충족 후보 확정 차단
- 회의 조건 카드 직접 수정 및 참석 응답 변경 후 재계산
- 회의 생성, 목록 조회, 제목 수정, 취소 시뮬레이션
- 확인 요청 ID 기반 중복 확정 방지와 확정 직전 서버 재검사
- 회의 버전 및 추천 기준 해시로 오래된 후보 확정 차단
- 확정 회의의 로컬 파일 저장 및 새로고침 후 복구
- 미완료 대화의 서버 버전 저장, 로컬 복구, 다중 탭·기기 충돌 차단(API Key는 디스크에 저장하지 않음)
- 오프라인 상태 안내, 입력 임시 저장, 실패 요청 재시도
- 데스크톱, 태블릿, 모바일 반응형 UI와 키보드 포커스 상태
- Google Calendar, Microsoft Graph, iCal, CalDAV 공급자를 추가할 수 있는 인터페이스

## NODI PRD v10.3 반영

- Design System v2.0의 Blue, Lavender, Neutral, Status 역할 토큰과 Pretendard 타입 규격을 적용했습니다.
- 버튼 크기와 라운드, 44px 이상 터치 영역, 모바일 바텀시트, 3-dot 로딩, 키보드 포커스와 reduced-motion 대응을 반영했습니다.
- 챗봇을 중심으로 자연어 입력, 한 번에 하나의 질문, 선택형 응답, 수정 가능한 회의 요약, 추천 카드 흐름을 구성했습니다.
- 사람의 중요도와 일정 확정 조건을 분리하고, 확정 가능 여부를 추천 점수보다 먼저 표시합니다.
- 추천, 회의 시간 확정, 초대 전송, 외부 캘린더 반영 상태를 각각 구분합니다.
- 추천 카드에 캘린더상 빈 시간, 직접 가능 응답, 충돌, 미확인, 최종 확인 시각을 분리해 표시합니다.
- 참석 가능 시간은 생성자가 직접 입력하거나 참석자별 전용 초대장으로 받을 수 있으며, 초대 응답은 주최자 화면에 5초 간격으로 자동 반영됩니다.
- 동일한 Groq Key로 연결한 로컬 환경 간에는 서버 초안을 복구하고, 오래된 버전의 덮어쓰기를 차단합니다.
- 모바일 하단 내비게이션, 동적 뷰포트, Safe Area, 서버 저장·오프라인·충돌 상태를 반영했습니다.
- 실제 Google OAuth, 이메일 발송, 조직 계정 인증은 외부 자격 증명과 정책이 필요해 현재 완료 상태로 표시하지 않습니다.

## 실행

Node.js 20 이상이 필요합니다.

```bash
npm install
npm run dev
```

브라우저에서 [http://localhost:5173](http://localhost:5173)을 열고 Groq Console에서 발급한 API Key를 입력합니다. 프론트엔드는 Vite 개발 서버, API는 `http://localhost:3001`에서 실행됩니다.

프로덕션 빌드 확인:

```bash
npm run build
NODE_ENV=production npm start
```

프로덕션 모드에서는 Node 서버가 `dist` 정적 파일도 함께 제공합니다. 기본 주소는 [http://localhost:3001](http://localhost:3001)입니다.

## 테스트

```bash
npm test
```

테스트는 필수 정보 누락, 잘못된 날짜 범위, 중복 참석자 제거, Free/Busy·직접 응답 병합, 미응답 처리, 확정 조건 위반, 추천 버전 무효화, 중복 확정 멱등성, 참석자별 초대 권한·만료, 서버 초안 충돌, 파일 복구, 주말 후보 없음 등을 확인합니다. Groq API 오류, 사용량 제한, 응답 형식 오류는 서버에서 사용자용 오류로 변환합니다.

## API Key 보안

- Key는 소스 코드, 브라우저 저장소, 데이터베이스, 로그에 기록하지 않습니다.
- 브라우저에는 `HttpOnly`, `SameSite=Strict` 세션 쿠키만 설정합니다.
- Key는 서버 프로세스 메모리에만 저장되고 연결 해제 또는 4시간 비활성 후 폐기됩니다.
- 서버 재시작 시 모든 세션이 폐기됩니다.
- 미완료 회의 조건과 대화는 새로고침 복구를 위해 브라우저 `localStorage`와 서버 `data/drafts.json`에 저장합니다. API Key는 두 곳 모두에 포함하지 않습니다.
- 이 방식은 로컬 MVP용입니다. 공개 배포 전에는 사용자 인증, 서버 측 세션 저장소, CSRF 방어, 비밀 관리, 요청 제한을 추가해야 합니다.

일정 데이터는 2026-10-28부터 2026-10-30까지 준비되어 있습니다. 다른 날짜도 근무 시간 기준 후보를 만들지만 등록된 충돌 일정은 없습니다. 직접 응답이 있는 사람은 그 응답을 우선하고, 미응답자는 연결된 데모 캘린더의 Free/Busy를 사용합니다. 둘은 추천 카드에서 별도 수치로 표시됩니다. 모든 결과는 UI에 `데모 데이터`로 표시됩니다. 초대장은 기기의 공유창 또는 링크 복사로 전달하며, 메일·메신저 서버가 실제로 자동 발송했다고 표시하지 않습니다.

확정된 회의는 기본적으로 `data/meetings.json`에 저장됩니다. 경로를 바꾸려면 서버 실행 전 `NODI_DATA_PATH`를 지정합니다. 이 파일은 Git에서 제외되며, 단일 로컬 프로세스용 저장소입니다.

응답 링크와 참석자 응답은 `data/invitations.json`에 저장됩니다. `NODI_INVITATION_DATA_PATH`로 경로를 변경할 수 있습니다. 주최자 토큰과 참석자별 192-bit 응답 토큰을 분리하고 응답 링크는 7일 후 만료됩니다. 공개 배포 전에는 이 링크 소유 방식을 조직 계정 인증과 이메일 소유 확인으로 교체해야 합니다.

서버 초안은 `data/drafts.json`에 저장되며 `NODI_DRAFT_DATA_PATH`로 경로를 변경할 수 있습니다. 로컬 MVP는 API Key의 SHA-256 해시를 작업 공간 식별자로 사용해 동일한 Key로 접속한 환경 간 복구를 지원합니다. 실제 서비스에서는 이 식별자를 인증된 사용자·조직 ID로 교체해야 합니다.

## 추천 점수

점수는 `server/recommendation.ts`에서 아래 항목을 고정 가중치로 계산합니다.

- 참석 가능 비율: 최대 65점
- 일정 확정 조건 충족: 20점
- 선호 시간대 일치: 10점
- 모든 참석자 일정 확인: 5점

AI는 회의 정보를 구조화하고 질문을 만드는 데만 사용합니다. 가능 여부와 점수는 생성하지 않습니다.

## 캘린더 확장

`server/calendar.ts`의 `CalendarProvider`를 구현하면 공급자를 추가할 수 있습니다.

- Google Calendar: OAuth와 Free/Busy, 이벤트 CRUD 구현
- Microsoft 365: Microsoft Graph OAuth와 Schedule, 이벤트 CRUD 구현
- iCal: 읽기 전용 공급자
- CalDAV: 서버 권한에 따른 읽기 및 쓰기 공급자

실제 공급자에서 이벤트 생성 응답을 받은 뒤에만 UI 상태를 확정으로 전환해야 합니다. 현재 미연동 공급자는 성공 상태로 표시하지 않습니다. 데모 회의도 `회의 시간 확정`, `캘린더 미반영`, `초대 미전송`을 별도 상태로 보여 줍니다.

## 현재 범위

Slack 및 Teams 채널, 대규모 동시 사용자 처리, 고가용성, 엔터프라이즈 감사 기능은 포함하지 않았습니다. 실제 OAuth 캘린더 연동과 이메일·서비스 알림도 인터페이스와 UI 상태만 준비되어 있습니다. 파일 저장소는 단일 로컬 프로세스용이며 사용자 인증·조직 권한·동시성 제어가 없으므로 공개 다중 사용자 배포에는 사용할 수 없습니다.

## 사용성 검증

PRD v10.3의 정성 사용자 테스트는 실제 사용자 6~8명을 모집한 뒤 수행해야 하는 제품 검증 단계입니다. 현재 저장소에는 실행 가능한 챗봇 중심 MVP와 자동화 QA만 포함하며, 검증하지 않은 KPI 목표를 실제 성과로 표시하지 않습니다. 테스트에서는 회의 계획 완료율, 미연동 응답 완료율, 추천 상태 이해도, 오류 복구, 모바일 과업, 기기 전환 복구 성공 여부를 기록합니다.
